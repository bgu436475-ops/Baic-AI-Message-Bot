# 全球 AI 重大事件与分层简报设计

## 背景

现有两阶段编辑流水线强调技术证据、可行动性和具体参数，适合专业开发者，但会把缺少代码、API 或操作建议的全球重大事件排除在外。2026-07-29 的自动简报从 74 条候选中粗筛 20 条，最终只保留两个 GitHub 项目；同时出现中文标题和中文摘要为空的问题。结果虽然通过了技术硬门槛，却不适合普通群成员快速了解全球 AI 进展。

本次改造保留原有技术决策榜，同时新增面向非技术读者的“全球 AI 重大事件”独立编辑通道。两个通道分别筛选、评分和去重，最后合并为一份分层简报。

## 目标

- 每日最多输出 5 条全球 AI 重大事件，不使用低价值内容补足数量。
- 让非技术读者能够在一分钟内理解当天最重要的全球 AI 叙事。
- 保留原有“今日必看、值得试用、观察项”技术决策榜。
- 所有正式发布内容必须包含完整中文标题和中文解释。
- 飞书标题不再直接链接 GitHub；原始链接统一放在清晰的“查看原文”位置。
- 网页展示完整全球事件和技术分榜，飞书保持适合群聊阅读的长度。
- 新功能先在隔离分支进行无飞书发送的验证，通过人工预览后再合并 `main`。

## 非目标

- 不把简报改造成追求覆盖率的行业热榜。
- 不降低原有技术决策榜的证据门槛。
- 不允许未经核验的传闻、预测或纯观点进入全球重大事件。
- 不要求全球重大事件必须提供操作建议、代码或技术参数。
- 不在本阶段引入新的付费新闻 API。

## 总体架构

流水线改为双通道：

```text
候选采集
  ├─ 全球事件预筛 → 事件原文核查 → 全球事件硬门槛 → 全球事件评分与去重
  └─ 技术候选预筛 → 原文核查 → 原有技术硬门槛 → 技术评分与分榜
                         ↓
                 跨通道事件级去重
                         ↓
          一分钟总览 → schema v4 → 飞书与网页
```

两个通道共享候选采集、原文读取和历史状态，但使用不同的准入规则与评分。若同一事件同时满足两个通道，优先进入全球重大事件；只有该事件还包含独立的开发、试用或部署增量时，技术榜才保留对应技术角度。

## 全球重大事件通道

### 分类

每条全球事件只能有一个主分类：

- `models_products`：模型与产品
- `companies_business`：公司与商业
- `policy_regulation`：政策与监管
- `research_breakthroughs`：科研突破
- `adoption_society`：大众应用与社会影响

同一分类每日最多 2 条，避免单一公司或单一叙事占据整个栏目。

### 来源

来源按以下优先级采集和核验：

1. 头部公司官方公告、产品发布页、模型卡和公开演示。
2. 政府、监管机构、法院、法案原文和正式政策文件。
3. 公司财报、投资者关系公告和监管申报。
4. 原始论文、研究机构公告和公开实验结果。
5. Reuters、Bloomberg、Financial Times、AP 等可靠媒体，用于发现事件和交叉核验。

覆盖对象包括但不限于 OpenAI、Anthropic、Google、Microsoft、Meta、NVIDIA、xAI、DeepMind、字节跳动、阿里、腾讯、百度和 DeepSeek。GitHub 项目原则上只进入技术通道，除非其影响已经超出开发者生态并构成全球性事件。

### 强制准入条件

全球重大事件必须同时满足：

1. 事件已经发生，而非预测、传闻或单纯观点。
2. 默认发生在最近 48 小时；回看最多 7 天时必须显示实际事件日期。
3. 至少有一个可访问的官方或原始来源；若原始来源暂不可用，则必须有两个相互独立的可靠媒体来源。
4. 对模型或产品能力、公司经营、政策规则、科研结论或公众使用产生明确变化。
5. 能明确说明发生了什么、为什么重要以及影响哪些群体。
6. 中文标题、中文事件说明和中文重要性解释均非空。

以下内容强制淘汰：

- 尚未证实的传闻、匿名爆料或预测。
- 只有融资金额，且没有产品、客户、收入、算力或战略变化。
- 只有高管观点，没有已经发生的事实变化。
- 只有政策方向，没有正式文本、具体条款或明确进度。
- 标题与来源正文中的实体、数字或日期冲突。
- 科研重大结论没有原始论文或独立验证。
- 与过去 7 天事件高度重复，且没有新增数字、条款、能力或业务进展。

### 独立评分

全球事件使用 100 分制：

- 影响范围：30
- 全球相关性：20
- 时效性：20
- 证据质量：15
- 信息增量：10
- 表达清晰度：5

总分低于 65 不进入栏目。每日最多 5 条，可以为 0 条，不使用低分内容补足。

## 技术决策通道

原有技术通道继续使用具体变化、可核查原始来源、影响对象和建议行动等硬门槛，并保留：

- 今日必看：最多 5 条
- 值得试用：最多 3 条
- 观察项：最多 3 条

网页展示完整技术分榜。为控制飞书卡片长度，飞书按技术分数从三个分榜中合计展示最多 5 条，并明确标注所属分榜；完整内容通过网页查看。

## 中文编辑要求

正式发布前增加确定性的中文完整性校验：

- `title_zh`、`what_happened_zh` 和 `why_it_matters_zh` 不得为空或只含空白。
- 不允许直接使用 `owner/repository` 作为面向普通读者的标题。
- 标题必须说明主体和事件，例如“某公司发布某模型”或“某地区通过某项 AI 规则”。
- 中文说明不得依赖英文术语才能理解；必要术语首次出现时给出中文解释。
- 禁止使用“意义重大”“展示潜力”“值得关注”等无事实支撑的套话。
- 若模型输出缺少中文字段，流水线必须尝试一次受证据约束的中文修复；修复后仍不完整则淘汰该条，不允许发布空字段。

## 数据结构

简报升级为 `schema_version: 4`，核心结构如下：

```json
{
  "schema_version": 4,
  "run_status": "published",
  "generated_at": "ISO-8601",
  "daily_narrative_zh": "两至三句中文总览",
  "global_events": [
    {
      "event_id": "稳定事件标识",
      "category": "models_products",
      "title_zh": "完整中文标题",
      "what_happened_zh": "发生了什么",
      "why_it_matters_zh": "为什么重要",
      "affected_groups_zh": ["影响群体"],
      "key_facts": ["数字、日期或条款"],
      "source_name": "来源名称",
      "source_url": "https://...",
      "supporting_urls": ["https://..."],
      "published_at": "ISO-8601",
      "score": {
        "impact": 0,
        "global_relevance": 0,
        "recency": 0,
        "evidence_quality": 0,
        "information_gain": 0,
        "clarity": 0,
        "total": 0
      }
    }
  ],
  "boards": {
    "must_read": [],
    "try_now": [],
    "watch": []
  },
  "items": []
}
```

`items` 继续保存技术分榜的扁平兼容视图。`global_events` 不重复写入 `items`，防止现有技术统计被改变。

### 状态规则

- `published`：`global_events` 或技术 `items` 至少一个非空。
- `no_qualifying_items`：`global_events`、三个技术分榜和 `items` 全部为空。
- 只有全球事件时允许正常发布。
- 只有技术事件时允许正常发布。
- 两个通道都为空时发送正常空榜卡，不视为工作流失败。

## 飞书展示

卡片顺序固定为：

1. 标题与日期。
2. “一分钟读懂今天”中文总览。
3. “全球 AI 重大事件”栏目，最多 5 条。
4. “技术与工具”栏目，最多 5 条。
5. 候选数量、核验数量和网页入口。

全球事件单条格式：

```text
🌍 [分类] 完整中文标题
发生了什么：……
为什么重要：……
影响：……
关键事实：……
来源：来源名称 · 查看原文
```

标题使用纯文本，不把整段标题直接绑定到 GitHub 或其他网站。链接只出现在“查看原文”。技术项目仍允许链接 GitHub，但同样使用完整中文标题和独立的原文入口。

若内容超过飞书 20 KB 限制，按以下顺序缩减：

1. 保留所有全球事件的标题、发生内容和来源。
2. 缩短全球事件的影响说明和关键事实数量。
3. 减少飞书技术条目数量。
4. 不得截断链接或发送不完整字段。

## 网页展示

网页顶部新增“全球 AI 重大事件”专区和五类筛选标签。其下保留原有技术分榜。中英文切换继续生效，但中文是默认且必须完整。每条全球事件展示关键事实、事件日期、来源名称和原文入口。

网页 schema 校验兼容 v3 历史简报；新生成数据必须是 v4。v3 仅用于读取旧记录，不允许新工作流继续生成 v3。

## 去重

全球事件指纹由主体、事件类型、产品或政策、关键变化和生效日期组成。过去 7 天内指纹相同且没有实质更新时淘汰。以下变化可视为实质更新：

- 新增或变化的参数、价格、用户数、收入或算力数字。
- 正式发布、正式生效或适用范围变化。
- 新增地区、客户、合作方或监管结果。
- 原先传闻变为官方确认。

跨通道去重发生在两个通道完成内部筛选后。若全球事件已入选，技术通道必须证明存在独立的开发者行动或工具变化才能保留，否则删除技术重复项。

## 错误处理与可观测性

- 每个通道分别记录候选数、核验数、入选数和主要淘汰原因。
- 单个来源失败不阻断整个简报，但必须记录来源名称和失败原因。
- 全球事件中文字段不完整时记录 `missing_chinese_explanation`。
- 可靠媒体只能作为发现来源但无法完成核验时记录 `global_event_unverified`。
- 全球事件通道失败而技术通道成功时，工作流失败，不发送缺少重大事件栏目的降级简报，防止悄然退回旧行为。
- 技术通道失败而全球事件通道成功时同样失败。
- 两个通道都正常执行但零入选时发送正常空榜卡。

## 测试与安全验证

### 自动测试

- 全球分类映射和分类上限。
- 全球事件六项强制准入条件。
- 65 分阈值和 100 分评分求和。
- 48 小时窗口及最多 7 天回看标记。
- 单一原始来源与双媒体交叉核验规则。
- 全球事件与技术事件的跨通道去重。
- 中文字段为空、仓库名标题和空泛句式的发布阻断。
- schema v4 状态与数组一致性。
- 飞书栏目顺序、明确原文入口和 20 KB 大小限制。
- 网页 v4 渲染和 v3 只读兼容。

### 分支验证

1. 在 `codex/global-major-events` 上运行 Python 和网页完整测试。
2. 使用固定样本生成一份包含五类全球事件与技术条目的端到端预览。
3. 运行分支工作流的验证模式，不读取生产飞书 webhook，不发送群消息，不写入 `main`。
4. 检查预览中没有空中文字段、直接 GitHub 仓库标题或跨栏目重复。
5. 将飞书卡片预览、网页预览、测试结果和 commit message 交给用户。
6. 只有在用户明确批准后才合并到 `main` 并启用正式发送。

## 验收标准

- 非技术读者可以仅阅读全球重大事件栏目理解当天主要 AI 变化。
- 有合格全球事件时，飞书卡片顶部至少包含 1 条且最多 5 条全球事件。
- 每条全球事件都有完整中文标题、事实说明、重要性解释、影响群体、日期和原文链接。
- 技术榜不再占据整份简报，GitHub 项目不会被误当成全球重大事件。
- 全球事件与技术榜之间没有无增量重复。
- 正式工作流生成 schema v4，网页和飞书均能正确读取。
- 所有自动测试通过，分支验证不向生产群发送消息。
