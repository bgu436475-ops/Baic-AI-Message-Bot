# 证据约束行动编辑器设计

日期：2026-07-28
状态：已获用户批准
目标仓库：`bgu436475-ops/Baic-AI-Message-Bot`

## 问题

2026-07-28 的流水线收集 68 条候选、核查 19 条，但 19 条全部命中
`missing_action`。证据提取器被要求只能提取原文事实，而原文通常不会直接
提供面向读者的行动建议；把 `recommended_action` 同时当作原文证据字段和
硬门槛，造成系统性空榜。

## 设计选择

采用确定性的“行动编辑器”，放在证据结构化和硬门槛之间：

```text
结构化证据
  → 程序校验证据锚点
  → 程序绑定来源属性
  → 证据约束行动编辑器
  → 硬门槛
```

不增加第二次模型调用。模型继续只负责提取事实；程序根据已经结构化的
`concrete_changes`、`affected_audience`、`affected_area`、
`change_type` 和 `action_horizon_days` 生成一条中文行动建议。

## 行动生成规则

- 缺少具体变化、影响对象或影响内容时，不生成行动，继续由硬门槛淘汰。
- 价格和成本变化：要求重新计算成本并对比当前方案。
- API、SDK、模型、版本或发布变化：要求先在非生产环境验证兼容性、性能和
  成本，再决定是否采用。
- 政策和条款变化：要求核对适用范围、生效时间并更新合规清单。
- 基准和评测变化：要求使用自身任务集复测，不能直接依据公开基准改变选型。
- 仓库和开源项目变化：要求在隔离环境核查安装、许可证和维护状态。
- 其他具体变化：要求在限定时间内小范围验证对应影响内容。

每条建议必须包含：

- 影响对象；
- 行动时间；
- 影响内容；
- 来自首个具体变化的简短“依据”。

行动编辑器不得发明数字、版本、日期、实体或业务结论。模型输出的原始
`recommended_action` 不作为最终结果，避免无法审计的自由建议绕过程序规则。
最终行动仍受现有长度、敏感信息清理和硬门槛约束。

## 失败与安全边界

- 无具体变化：保留 `missing_concrete_change` 和 `missing_action`。
- 无影响对象：保留 `missing_affected_audience` 和 `missing_action`。
- 无影响内容：保留 `missing_affected_area` 和 `missing_action`。
- 证据锚点无效或一手来源不可确认：即使生成行动也不得进入主榜。
- 行动生成不改变来源验证、证据锚点、去重、计分或分榜规则。

## 验证

- 单元测试覆盖价格、发布、政策、基准、开源和通用模板。
- 测试证明缺失任一必要输入时不会生成行动。
- 流水线测试证明原本仅因 `missing_action` 被拒的合格证据可以继续进入分榜。
- 测试证明无效证据锚点和未确认一手来源仍不能绕过硬门槛。
- 完成后运行完整 Python 测试套件和差异检查。
